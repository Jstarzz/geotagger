# GeoTagger API Guide

## Purpose

GeoTagger is a self-hosted IP-to-country lookup service. The public API accepts one IP address and returns the country name resolved from the locally stored MaxMind GeoLite2 Country database.

Production/staging base URL:

```text
https://geo.itsjosiahdavis.dev
```

The service is intended for machine-to-machine use. It does not provide a browser login flow.

## Authentication

Every lookup request requires a bearer token in the form:

```text
<key-id>.<secret>
```

Example header:

```http
Authorization: Bearer azure-prod.<secret>
```

Only the SHA-256 digest of the secret is stored server-side. Generate a new caller credential with:

```bash
go run ./cmd/keygen azure-prod
```

The command prints:

- a `client token` to give to the caller; and
- an `API_KEYS entry` containing the key ID and SHA-256 digest to store on the server.

Treat the client token like a password. Do not commit it, place it in source code, or log it.

## Country lookup

### Request

```http
POST /v1/country
Authorization: Bearer <client-token>
Content-Type: application/json

{"ip":"8.8.8.8"}
```

The request body must contain exactly one JSON object with an `ip` field. Unknown fields are rejected.

### Success

```http
HTTP/2 200
Content-Type: application/json
Cache-Control: no-store
X-Request-ID: c75bb0a033c44dd87a9969df059dd6b4
```

```json
{"country":"United States"}
```

`X-Request-ID` is generated by GeoTagger and is also stored with the audit record. Preserve it in the calling application's logs so an API response can be correlated with its audit event without logging the queried IP.

### cURL example

```bash
curl -i \
  -H "Authorization: Bearer $GEOTAGGER_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"ip":"8.8.8.8"}' \
  https://geo.itsjosiahdavis.dev/v1/country
```

## Public-address policy

By default GeoTagger only permits public, globally routable IP targets. The address must be:

- syntactically valid;
- global unicast;
- not private;
- not loopback; and
- not link-local.

For example, this request is rejected:

```json
{"ip":"10.0.0.1"}
```

with:

```http
HTTP/2 422
```

```json
{"error":"IP address is not a permitted public address"}
```

This is intentional. A device on a LAN may have an address such as `192.168.1.20`, but a geolocation caller should submit the device's trusted public Internet address, not its private LAN address.

## Response and error contract

| Status | Meaning | Typical response |
|---:|---|---|
| 200 | Country resolved | `{"country":"United States"}` |
| 400 | Invalid JSON/request shape | `{"error":"body must be JSON with an ip field"}` |
| 401 | Missing or invalid bearer token | `{"error":"unauthorized"}` |
| 413 | Request body exceeds configured limit | `{"error":"request body too large"}` |
| 422 | Invalid IP syntax | `{"error":"invalid IP address"}` |
| 422 | Private/reserved target rejected | `{"error":"IP address is not a permitted public address"}` |
| 404 | Valid public IP has no country entry in the current MMDB | `{"error":"country not found"}` |
| 500 | Local lookup failed | `{"error":"lookup failed"}` |
| 503 | Durable audit transport unavailable | `{"error":"audit transport unavailable"}` |

A `404` is an application result, not necessarily an infrastructure failure. Some public anycast ranges may have no country entry in a particular GeoLite2 snapshot.

## Retry guidance

Callers should not blindly retry all failures.

- `400`, `401`, `413`, and `422`: fix the request or credential; do not automatically retry unchanged input.
- `404`: treat as "country unavailable" for that IP/database snapshot.
- `500`: retry only if the caller's policy permits it.
- `503`: retry with bounded exponential backoff because GeoTagger intentionally fails closed when the durable audit transport cannot acknowledge the request.

Suggested machine-client behavior:

1. set a finite HTTP timeout;
2. record `X-Request-ID` on every response;
3. retry only transient `5xx` responses;
4. cap retry count and total elapsed time; and
5. never log bearer tokens.

## Audit/privacy behavior

Successful lookups are returned only after NATS JetStream acknowledges the audit event. ClickHouse persistence happens asynchronously after that durable queue acknowledgement.

Default audit behavior:

- raw queried IP is not stored;
- the IP is represented by HMAC-SHA256;
- caller ID, request ID, country, result status, lookup latency, and MMDB version are recorded;
- authentication failures are audited without retaining the target IP; and
- ClickHouse audit rows have a 30-day TTL.

## IPv6

IPv6 is supported. Example:

```bash
curl -i \
  -H "Authorization: Bearer $GEOTAGGER_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"ip":"2001:4860:4860::8888"}' \
  https://geo.itsjosiahdavis.dev/v1/country
```

## Health and metrics

The public service exposes only the lookup API on port 8080 through the Cloudflare Tunnel. Health, readiness, and Prometheus metrics are on the internal administrative listener on port 9090 and are intentionally not published through the public Kubernetes Service.

Internal endpoints:

```text
GET /healthz
GET /readyz
GET /metrics
```

Use `kubectl port-forward` or another administrator-only path when inspecting them.
